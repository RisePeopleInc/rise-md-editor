# Changelog

All notable changes to Rise MD Editor are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Unit test coverage for the clipboard-paste / serialize post-process pipeline** ([RAISE-40](https://risepeople.atlassian.net/browse/RAISE-40)). Adds 69 new assertions across the ~10 regex / preprocessing rules in `clipboardPaste.ts` and `emptyParagraphMarker.ts` — the rules tuned across five RAISE-39 smoke-test iterations to make Word / Outlook / Google Docs / Notion paste land as clean markdown. Covers the `looksLikeMarkdown` strong-marker heuristic (positive: headings, fences, links, images, bold, Google-Docs escapes, GFM table rows; negative: the Word plain-text bullets, Outlook reply-quote markers, and plain ordered lists that motivated tightening), the `cleanupGoogleDocsMarkdown` quirk fixes (double-wrapped-link unwrap, mid-heading and list-start digit-dot escapes, table-cell hash escape), `unescapeHeadingNumberDot` (full heading-line scan, idempotence, no-touch outside headings), the Word-HTML preprocessing path (`preprocessClipboardHtml` head/style drop, `MsoTitle`→`h1` promotion, thead-less table header promotion, multi-paragraph cell unwrap), `sanitizeTurndownOutput`, and `getMarkdownFromClipboard` branch selection (text/plain-wins, HTML fall-through, Turndown-failure fallback). Also pins every `stripEmptyParagraphMarkers` shape (standalone, `*`/`-`/`+`/ordered/task/blockquote/indented `<br />` markers) and its code-region awareness (mid-line and fenced `<br />` preserved). The DOM-dependent functions run under a per-file `// @vitest-environment jsdom` docblock; `jsdom` is added as a dev dependency and `sanitizeTurndownOutput` was promoted from module-internal to `export` to make it directly testable — no public API consumers changed. Realistic `.html` / `.txt` / `.expected.md` fixtures (Google Docs policy, Word headerless table, Outlook reply, Notion mixed) live under `src/renderer/state/__tests__/fixtures/` and are Prettier-ignored so the byte-exact inputs and expected outputs survive a format pass (suite: 101 → 170 tests passing).
- **Unit test coverage for the comment-rendering helpers** ([RAISE-41](https://risepeople.atlassian.net/browse/RAISE-41)). Locks in the regex / preprocessing rules in `commentDecorations.ts` and `markdownItComments.ts` tuned across RAISE-31's four smoke-test rounds — the same regression-gate concern as RAISE-40. Covers `unescapeCommentDelimiters` (escaped comment-open strip, inner-content unescape for the full markdown-syntax set including the gfm-autolink-literal `:` / `.` / `@` trio, the literal `\\<!--` edge case that must NOT be unescaped, and idempotence), `unescapeIndentEntities` (`&#x20;` → space, single and repeated), the `buildDecorations` doc walk (inline-html comment decoration, the `// note` line-comment fast-path, code-block skip, and non-disturbance of a sibling prose paragraph — exercised against a minimal ProseMirror schema mirroring just the node shapes the function inspects, so no full editor or DOM is needed), and the `markdownItComments` preview rule (inline and line comments, recursive inner-content parse, the mid-line `//` URL guard, and code-block skip). `buildDecorations` was promoted from module-internal to `export` to make it directly testable — no public consumers changed. The EditorView plugin-lifecycle path (decorate-on-mount / re-decorate-on-type / decorate-on-paste) is left as a follow-up; `buildDecorations` is the logic it drives. (suite: 170 → 202 tests passing.)
- **Rise-branded file icon for markdown documents** ([RAISE-65](https://risepeople.atlassian.net/browse/RAISE-65)). Files in the claimed markdown extension family (`.md`, `.markdown`, `.mdown`, `.mkd`, `.mkdn`, `.mdwn`, `.mdtxt`, `.mdtext`) now show a custom document icon in Finder and Explorer instead of the generic system page — a white page silhouette with a folded top-right corner (the universal "document" dog-ear) and the orange Rise double-ring mark centred on it. This is the document icon, distinct from the app icon. Same artwork on both platforms, driven by a single SVG design source (`build/file-icons/md.svg`) rasterized to `md.icns` (macOS) and `md.ico` (Windows) via the new `scripts/generate-file-icons.sh`, and wired into every `fileAssociations` entry in `electron-builder.yml` (electron-builder picks the right binary per platform). Closes one of the follow-up items the RAISE-44 file-association work explicitly left out of scope.
  - Notes: the icon only applies to packaged builds — `npm run dev` and `npm run build` (electron-vite) don't read `electron-builder.yml`, so it's verifiable only after `build:mac` / `build:win` packaging, and the OS icon cache may need a refresh to pick up a changed icon. The artwork is tuned for legibility at 16×16 (the dominant Finder / Explorer size): page + rings only, no fine detail or text. `png-to-ico` ignores the requested source sizes and always emits its own canonical set (16/32/48/256), so the generation script renders only those.
- **Link popover in Edit mode** ([RAISE-86](https://risepeople.atlassian.net/browse/RAISE-86)). Clicking a link in Edit (WYSIWYG) mode used to only position the cursor — there was no way to open, edit, or remove the link without leaving the editor. Now, whenever the caret lands inside a link (by click, by arrow-key navigation, or any other cursor move), a small floating popover appears anchored just below the link (or above it, when the link sits near the bottom of the viewport) with three controls — **Open** (opens the URL in your default browser), **Edit** (swaps in an inline URL field with Apply / Cancel), and **Remove** (strips the link, keeping the visible text) — plus the link's URL and a muted one-line tip: _"⌘-click to open the link directly in your browser"_ (macOS) / _"Ctrl+click…"_ (Windows / Linux). The popover dismisses on Escape, a click outside, scrolling, or when the cursor leaves the link. **Cmd/Ctrl-click is unchanged** — it still opens the URL directly in the system browser with no popover and no stray selection (RAISE-87), and holding ⌘/Ctrl while hovering a link now shows a pointer cursor to signal that shortcut. Right-clicking a link shows only the context menu (not the popover as well). Right-clicking a link now shows **Open Link / Edit Link… / Remove Link** in the context menu (replacing the single "Edit Link…" item); right-clicking elsewhere still shows "Add Link…". Styling mirrors the existing image tooltip (Rise design tokens, depth-1 shadow), so the two floating surfaces look consistent. Read / Split / Source mode link behaviour and the image tooltip are untouched.
  - Notes: detection is a ProseMirror `$prose` plugin whose `view().update` runs after every transaction, so it covers click and keyboard cursor movement uniformly. Edit and Remove operate on the link mark's full resolved range (not just the click point) via a direct `removeMark` / `addMark` transaction, so editing a bold or italic link preserves the surrounding marks. Three new menu actions (`context-open-link` / `context-edit-link` / `context-remove-link`) are wired through the `MenuActionType` union, the WYSIWYG context menu, and `WysiwygEditor`'s imperative handle.
- **New File button on the Welcome Screen** ([RAISE-83](https://risepeople.atlassian.net/browse/RAISE-83)). The no-file landing page now offers a third action — **New File** — alongside Open File and Open Folder, so starting a fresh document no longer requires reaching for the `File → New` menu. It sits leftmost (New File → Open File → Open Folder) and takes the primary button style; Open File is demoted to the secondary style so there's exactly one primary action on the screen. Clicking it runs the same code path as `File → New`, opening an empty untitled tab in Edit (WYSIWYG) mode. The two secondary buttons (Open File / Open Folder) were also aligned to the Rise Component Library's secondary-button spec — white resting fill, purple outline and label, fading to a solid purple fill with white text on hover — using the existing `--rise-interaction*` tokens (which are defined as the RCL `p450`/`p500`/`p550` palette, so the colours match the component library exactly).

### Changed

- **Read mode: task-list checkboxes are now clickable and save instantly** ([RAISE-85](https://risepeople.atlassian.net/browse/RAISE-85)). GFM task-list checkboxes (`- [ ]` / `- [x]`) in Read mode used to render greyed-out and static — a deliberate choice from RAISE-60, when Read mode was strictly read-only. They are now interactive: clicking one toggles the checkbox, rewrites the underlying markdown, and **silently writes the file to disk**. You stay in Read mode, the tab does _not_ become dirty, and there's no save prompt — the on-disk file and the in-memory buffer move together. This makes the common "tick off a checklist item while reading" gesture work without dropping into an edit mode. Mirrors the click-to-toggle already in Split-view's preview pane, but Split marks the tab dirty (its edits flow through the normal editor buffer) whereas Read mode persists immediately. **Behaviour change to note**: Read mode now mutates files on click where it previously never wrote to disk at all. Rapid clicks toggle correctly (each toggle is computed from the latest source and the writes are serialized). Untitled (never-saved) files can't be written silently, so toggling one there keeps the change in memory and marks the tab dirty until you save. If a write fails because the file is read-only or locked, the checkbox snaps back and a small non-modal notice ("This file is read-only — couldn't update.") appears instead of a blocking dialog. Scroll position is preserved across a toggle. Edit / Code / Split checkbox behaviour is unchanged.
  - Notes: the toggle math (flip the marker on a single source line, keyed by markdown-it's `list_item_open` token `.map[0]` offset by the frontmatter line count) is extracted into `src/renderer/state/taskListToggle.ts` and unit-tested, shared with SplitView's existing handler shape. The silent-save path adds a `setActiveContentSaved` method to `fileState` (sets `content` + `savedContent` + `editorBaseline` in one update, no `loadEpoch` bump) and an `onToggleTask` prop threaded ReadView → EditorContainer → App. The RAISE-78 scroll ref now seeds the scroll-restore effect (instead of the mount-time prop) so the content-driven re-render after a toggle doesn't jump the reader.
- **Stripped ~80 unused Monaco syntax-highlighting language packs from the renderer bundle** ([RAISE-82](https://risepeople.atlassian.net/browse/RAISE-82)). Monaco was wired through a bare `monaco-editor` barrel import, which resolves to `editor.main` and eagerly registers every language pack it ships — abap, solidity, freemarker2, postiats, perl, razor, clojure, ruby, redshift, pgsql, mysql, elixir, and ~70 more — plus the TypeScript / CSS / HTML rich-feature language services and their web workers. For a markdown editor where other languages only ever surface inside fenced code blocks, that's pure dead weight. The four renderer files that imported the barrel (`monaco-setup.ts`, `monaco-themes.ts`, `state/themeState.ts`, `components/editors/SourceEditor.tsx`) now import Monaco's core editor API (`monaco-editor/esm/vs/editor/editor.api`) instead, and `monaco-setup.ts` opts into a curated set of basic-language contributions — javascript, typescript, python, shell (bash), yaml, html, css, markdown, sql, go, rust, java, cpp (C + C++), csharp, xml, dockerfile, ini — plus the JSON rich feature, which together cover ~95% of the fenced code blocks people put in CLAUDE.md / SKILL.md files. Languages outside the curated set degrade gracefully: their fenced blocks render as plain, unhighlighted monospace, no errors. Net effect on the production renderer output: total `out/renderer` drops from **28 MB to 11 MB**, and the dropped TypeScript / CSS / HTML rich-feature workers (the 13.3 MB `ts.worker`, 1.9 MB `css.worker`, 1.2 MB `html.worker`) plus ~63 per-language chunks all vanish; only the shared editor worker, the JSON worker, and the 18 kept-language chunks remain. The main `index-*.js` shrinks ~166 KB (9.55 MB → 9.38 MB).
  - Notes: TypeScript can't resolve the `editor.api` deep specifier on its own — it treats the `.api` suffix as a file extension and strips it, then looks for a non-existent `editor` module (Monaco's package `exports` wildcard maps the subpath verbatim with no `types` condition for TS to follow). A `paths` alias in `tsconfig.web.json` points the specifier at the sibling `editor.api.d.ts` for type resolution only; Vite resolves the runtime `.js` independently via the package `exports` map, so bundler behaviour is unchanged.
- **Files opened from the OS now open in Edit mode, not Read mode** ([RAISE-84](https://risepeople.atlassian.net/browse/RAISE-84)). Double-clicking a `.md` file in Finder / Explorer, using "Open With → Rise MD Editor", or launching via a file association used to open the file in Read mode (the RAISE-60 default); they now open in the same Edit (WYSIWYG) mode as every other open path (sidebar click, drag-drop, `File → Open…`, recents, `File → New`). User feedback was that the common intent when opening a file from the desktop is to edit it, not just read it, so a single consistent default is less surprising than branching on launch context. Already-open tabs are unaffected — re-opening a file keeps whatever mode the tab is currently in. Mechanically this removes the `fromOs` flag that was threaded through the `open-path` menu-action payload; `loadFile`'s `initialMode` argument is retained (defaulting to `'wysiwyg'`) so a future "open in Read mode" preference can re-introduce a non-default mode without re-plumbing.

### Fixed

- **Read mode: text selection no longer breaks on scroll, and Cmd/Ctrl+C copies only the selected text** ([RAISE-78](https://risepeople.atlassian.net/browse/RAISE-78), [RAISE-79](https://risepeople.atlassian.net/browse/RAISE-79)). Selecting text in Read mode and then scrolling used to clear the highlight, and pressing Cmd/Ctrl+C after scrolling copied everything from the top of the document down to the selection end instead of just the selected text. Both were the same root cause: Read mode persisted its scroll offset by writing to `fileState` on every scroll event, and that React re-render corrupted the live DOM text selection — collapsing it and re-anchoring its range to document-start. A copy then reflected that corrupted, top-anchored range. The view now tracks its scroll offset in a ref and commits it to the tab only on unmount (tab switch, mode switch, or re-open), so scrolling no longer triggers a re-render and the selection stays intact. Per-tab scroll restore is unchanged. Diagnosed by instrumenting the live selection and clipboard during a repro — a single scroll tick was observed resetting the selection range to offset 0 of the document's first node.
- **Edit mode: Cmd/Ctrl-clicking a link no longer leaves a stray line-wide selection** ([RAISE-87](https://risepeople.atlassian.net/browse/RAISE-87)). Modifier-clicking a link in Edit (WYSIWYG) mode correctly opened the URL in the system browser ([RAISE-38](https://risepeople.atlassian.net/browse/RAISE-38)), but it also drew a purple selection box across the whole paragraph — and if the user then started typing they'd replace the selected paragraph rather than append to it. The open handler ran on the `click` event and called `preventDefault`, but ProseMirror moves the selection on `mousedown`, which fires first, so the suppression was too late. The handler now runs on mousedown in the capture phase (on the scroll container, an ancestor of ProseMirror's contentEditable), stopping the event before ProseMirror's selection logic sees it. The URL still opens and the cursor / selection is left untouched. Plain clicks are unchanged.
- **App theme: switching from Dark back to Follow System now reverts correctly** ([RAISE-88](https://risepeople.atlassian.net/browse/RAISE-88)). With the OS in light mode, choosing Dark and then Follow System left the app stuck on dark. `theme:set-app` set `nativeTheme.themeSource = 'system'` and then read `nativeTheme.shouldUseDarkColors` synchronously to resolve the appearance — but that value is stale for one event-loop tick after the flip, so it returned the previous forced-dark value, which both the IPC reply and the broadcast then carried. The handler now yields one tick before snapshotting / broadcasting when the preference is `system`, so the resolved appearance reflects the actual OS setting. Explicit Light / Dark choices are unaffected (they resolve straight from the preference, with no `shouldUseDarkColors` read).

## [1.0.0] — 2026-05-22

First stable release. Brings the toolchain current and zeroes out the public Dependabot dashboard via the four follow-up tickets spawned from the post-RAISE-57 triage (RAISE-67/68/69/70). Ships the open-source flip with MIT licensing per RAISE-57. Cleans up a batch of UX bugs surfaced during the v0.1.4 smoke-test pass (RAISE-59 / 66 / 72 / 73 / 74 / 75 / 76).

No user-data migration vs v0.1.4 — same editor.state.json keys, same recents store, same theme store. Existing v0.1.4 installs auto-update via electron-updater on next launch.

The entries below are the same content that appeared in `[Unreleased]` up through 2026-05-22; reorganised under this version heading at release time. Future changes go under a fresh `[Unreleased]` section above this one.

### Added

- **Periodic auto-update re-checks for long-running sessions** ([RAISE-21](https://risepeople.atlassian.net/browse/RAISE-21)). The auto-updater now re-polls GitHub Releases every 6 hours after the initial 5-second launch check, so users who keep the app open over weekends still pick up new versions without quitting and relaunching. Failures (offline / DNS hiccup at check time) are silently swallowed — the next tick recovers on its own, no error banner flicker. Checks are skipped while a download is already in flight or has finished waiting for restart, so the periodic loop never duplicates the existing download / install flow. When a periodic check does find an update, it surfaces through the same `update-available` → `update-downloaded` event path as the launch check, so the existing non-intrusive banner handles it (no surprise dialogs mid-edit). The interval is cleared on `before-quit` so the timer never leaks. The 6-hour cadence is a constant (`RECHECK_INTERVAL_MS`) near the top of `src/main/autoUpdater.ts` if release cadence ever motivates a tune.
- **OS file associations for markdown** ([RAISE-44](https://risepeople.atlassian.net/browse/RAISE-44)). Installing Rise MD Editor now claims the markdown extension family at the OS level so right-click → Open With (macOS Finder), Default Apps (Windows), and double-click-to-launch flows all work. Claimed extensions: `.md`, `.markdown`, `.mdown`, `.mkd`, `.mkdn`, `.mdwn`, `.mdtxt`, `.mdtext`. **Deliberately not claimed**: `.txt` (too generic — would steal from system defaults like TextEdit / Notepad; we still _accept_ `.txt` via argv if a user manually sets us as the default for it) and `.mdx` (separate ecosystem). On macOS, electron-builder writes the `CFBundleDocumentTypes` and UTI declarations into the `.app` bundle's Info.plist; on Windows the NSIS installer writes per-user (`HKCU`) registry entries — no admin elevation needed, matches VS Code's default. Multi-select from Explorer (which concatenates every selected path into argv on a single launch) now opens all of them as tabs in one window — the previous `findFileArg` returned only the first match. The existing single-instance lock (RAISE-58 prep work) routes second-launch file paths through `app.on('second-instance')` so double-clicking a `.md` while the app is running opens a tab in the existing window rather than spawning a duplicate process. Files opened via the OS open in Read mode per RAISE-60. **Follow-up work tracked separately**: encoding fallback for UTF-16 / Latin-1 files, large-file (>10 MB) confirmation, realpath-based de-dup for symlinks, custom file icons in Finder / Explorer, Linux `.desktop` MIME-type registration, and a "make us your default?" first-launch prompt — all listed as out of scope in the ticket.
- **Drag-and-drop file/folder moves in the sidebar tree** ([RAISE-13](https://risepeople.atlassian.net/browse/RAISE-13)). Drag a file or folder onto a different folder row to move it. Dropping onto a file targets that file's parent. Drop-target folders get a tinted highlight ring while hovered. Invalid moves are disabled at drag time (no-drop cursor, no highlight) — same-parent no-ops, folder-onto-itself, folder-into-a-descendant. Name collisions surface a dialog and the existing item is preserved. Cross-device moves (workspace on one drive, destination on another) surface a clear "use your file manager instead" error rather than crashing — the copy+delete fallback is out of scope. Open tabs follow the move automatically: a file's tab path updates to the new location, and tabs for descendants of a moved folder follow too. The root row isn't draggable but IS a valid drop target (drop a file onto the workspace folder name to promote it to the top level). **Opt-drag (macOS) / Ctrl-drag (Windows / Linux)** flips the operation to a copy — the OS cursor switches from the move arrow to the `+` copy cursor live as you press / release the modifier. Same-parent copies auto-rename to `<stem> 2.<ext>`, `<stem> 3.<ext>`, etc. (lowest available integer, Finder-style); cross-folder copies require an unused name and surface a clear error on collision. Folder copies recurse through the subtree via `fs.cp`, so dragging a folder duplicates its full contents. Multi-extension files like `notes.tar.gz` keep the compound suffix intact during auto-rename — copy becomes `notes 2.tar.gz`, not the orphaned `notes.tar 2.gz`. **Drag a sidebar file INTO the editor** (instead of onto another tree row) and the editor inserts a reference to it at the drop point: in Edit mode an image file becomes a markdown image (`![name](relative/path.png)`), in Code or Split the file's relative path is inserted as plain text. Image-only for now — non-image sidebar files dropped into the editor are no-ops; future feature could extend to markdown-link or attachment-reference insertion. **Double-click on a non-markdown file in the sidebar** (e.g. `.html`, `.pdf`, `.png`) now opens it in the OS default application — your browser or VS Code for `.html`, Preview or Acrobat for `.pdf`, etc., per your system's file associations. Folders still expand/collapse on double-click; markdown files still open in-editor on single-click. The styling of non-markdown rows is updated to use the regular hover background and pointer cursor (they're actionable now via double-click) while keeping the muted text colour as a file-type hint.
- **Paste and Match Style** ([RAISE-51](https://risepeople.atlassian.net/browse/RAISE-51)). New `Cmd/Ctrl+Shift+V` accelerator pastes the clipboard content with all formatting markers dropped — no link marks, no bold / italic / strikethrough, no tables / lists / headings — bypassing the markdown / Turndown / image pipeline that regular `Cmd/Ctrl+V` runs through. Use case: copying a paragraph from a styled web article without dragging links and `<em>` markup along; pasting a code snippet that the source marked up as a table; quoting a passage without inheriting the source's link salad. Edit menu gains `Paste and Match Style` (macOS naming) / `Paste without Formatting` (Windows/Linux); the same item appears in the editor right-click context menu next to regular Paste in WYSIWYG, Source, Split, and the frontmatter textarea — gated on the clipboard actually containing text so the menu item is hidden for image-only clipboards. Image clipboards short-circuit to a no-op for paste-plain, matching Word's behaviour. In WYSIWYG the surface reads the clipboard's `text/html` slot and reduces it to its visible text content (with paragraph and heading boundaries preserved as line breaks, table cells joined with tabs), so a heading copied from inside the app pastes as `Header`, not `## Header`. In Source / Split, the `text/plain` slot inserts at the cursor verbatim — the user is editing raw markdown there and wants the markdown source. Both paths normalize `U+00A0` (non-breaking space — common web-page artifact) to ASCII space and strip `U+FEFF` (BOM). The regular Cmd/Ctrl+V pipeline (RAISE-39) is unchanged.
- **Read mode — fourth editor mode for read-only rendered markdown** ([RAISE-60](https://risepeople.atlassian.net/browse/RAISE-60), supersedes [RAISE-52](https://risepeople.atlassian.net/browse/RAISE-52)). Adds a `Read` option to the mode pill, sitting leftmost (Read → Edit → Code → Split). Renders the markdown through the same `markdown-it` pipeline as the Split-view preview pane but without an accompanying editor surface — no Monaco, no Milkdown, no contenteditable. Layout matches the WYSIWYG centered max-width column. Per-tab scroll persistence via a new `readScrollPosition` Tab field. **Mode accelerators renumbered** to match the pill order: `Cmd+1` = Read, `Cmd+2` = WYSIWYG, `Cmd+3` = Source, `Cmd+4` = Split — pre-RAISE-60 these were `Cmd+1/2/3` for WYSIWYG/Source/Split. `Cycle Mode` (`Cmd+\\`) walks all four in pill order. `Cmd+A` in Read mode selects the preview content (scoped — does not select the sidebar / mode pill / status bar the way the default `webContents.selectAll()` would). **Default mode by launch context**: files opened via the OS (macOS `app.on('open-file')` from Finder double-click / "Open With", Win/Linux argv file-association) open in Read mode; files opened in-app (sidebar click, drag-drop, `File → Open…` dialog, recents, `File → New`) keep the existing WYSIWYG default. If a file is already open and the OS triggers another open, the existing tab activates with its current mode preserved — re-opening a file you're actively editing doesn't yank you back to Read. Mechanism: an optional `fromOs` flag threaded through the `open-path` menu-action payload, consumed by `loadFile`'s new `initialMode` arg.
- **Export to HTML** ([RAISE-53](https://risepeople.atlassian.net/browse/RAISE-53)). New `File → Export → HTML…` menu item produces a portable HTML rendering of the document, visually identical to the existing PDF export (same markdown-it pipeline, same prose styling, same fonts). The modal offers two image-bundling modes: **Inline** embeds images as base64 data URIs in a single self-contained `.html` file (good for email / Slack / archive); **External** copies images into an `assets/` folder alongside the HTML and packages the result as a `.zip` (good for hosting or unpacking to edit). Same range / strip-comments / open-after toggles as the PDF modal. Mode preference is persisted in localStorage so repeat exports don't re-ask. Exported HTML uses a WYSIWYG-matching layout (centered max-width column, surface-tone code blocks) rather than the print-tuned overrides used for PDF, and its inlined `<style>` block is minified at export time — comment+whitespace stripping alone drops it from ~20KB to ~6KB without changing any rendered byte.
- **Windows installers are now signed via Azure Artifact Signing** ([RAISE-58](https://risepeople.atlassian.net/browse/RAISE-58)). SmartScreen no longer shows the "Unknown publisher" warning on first install — the signed `.exe` chains up to Microsoft's trusted root and shows _Rise People Inc._ as the verified publisher. Signing happens during the CI build via electron-builder's `signtoolOptions.sign` callback ([`scripts/sign-windows.cjs`](scripts/sign-windows.cjs)) shelling out to Microsoft's Artifact Signing dlib + `signtool.exe`. The cert lives in Microsoft's FIPS 140-2 Level 3 HSM and never touches the runner; the runner authenticates to Azure via OIDC federation (no long-lived service-principal secret). Cost is ~$10/month (Artifact Signing Basic tier). The `build-win` job declares `environment: rise-md-editor-signing` so only authorized workflow runs can exchange their OIDC token for the cert-profile signing role. Full one-time provisioning recipe in [`docs/azure-signing-setup.md`](docs/azure-signing-setup.md). _(Note: Microsoft rebranded "Trusted Signing" → "Artifact Signing" in the Azure portal; older Microsoft Learn docs and the NuGet client package `Microsoft.Trusted.Signing.Client` still use the older name.)_
- **Automated release pipeline via GitHub Actions** ([RAISE-45](https://risepeople.atlassian.net/browse/RAISE-45)). Pushing a `v*` tag now triggers a parallel macOS + Windows build on GitHub-hosted runners that assembles the artifacts into a draft GitHub Release. macOS builds are code-signed and notarized (Apple Developer ID + notarytool); Windows signing landed shortly after via RAISE-58 above. A `workflow_dispatch` entry point with a `skip_signing` input lets contributors dry-run the macOS path without burning notary minutes. Operational details — secrets, troubleshooting — live in `docs/release-process.md`.
- **Test infrastructure (vitest + CI workflow)** ([RAISE-14](https://risepeople.atlassian.net/browse/RAISE-14)). Adds vitest as the unit-test runner for pure-logic surfaces in renderer and main, with the first test covering the `looksLikeFilenameExtension` / `looksLikeKnownTld` autolink gate that originally landed in RAISE-47. Tests live alongside the source under `__tests__/` directories and are discovered via the glob in `vitest.config.ts`. New `npm test` script runs the full suite once and exits — the `vitest run` (not `vitest`) form so it doesn't drop into watch mode in CI. A new `.github/workflows/ci.yml` runs `typecheck` + `lint` + `build` + `test` on every push to a non-main branch and every PR to main, mirroring the local pre-commit gate. The release pipeline (`release.yml`) is untouched. Foundation for the dedicated fixture-coverage tickets (RAISE-35, 40, 41, 50) that will sit on top of it.
- **Unit test coverage for the RAISE-47 autolink discriminator family** ([RAISE-50](https://risepeople.atlassian.net/browse/RAISE-50)). - **Autolink now fires for URLs followed by sentence punctuation + space** ([RAISE-66](https://risepeople.atlassian.net/browse/RAISE-66)). Typing `Check out https://example.com. Next sentence.` used to leave the URL as plain text — the user had to backspace the period, let the space trigger autolink, then re-type the period. Root cause was in `findCompletedHits` (`src/renderer/state/autolinkOnType.ts`): the greedy URL regex matched `https://example.com.` (length 20), `TRAILING_PUNCT_RE` trimmed the period (length 19), but the boundary check then read `text.charAt(19)` — which is the stripped period, not the space that follows at index 20 — and rejected the hit. The fix introduces a `boundaryPos = matchEnd + punctStripped` that walks past any stripped trailing-punct chars before checking for whitespace; the URL's actual length still uses the trimmed match, so the period correctly stays in the source. Affects every char in `TRAILING_PUNCT_RE`'s set (`. , ! ? ; : ) ]`) — all eight cases plus stacked-punct (`?!`) now autolink correctly. `WWW_URL_RE` benefits when the URL has a path with trailing punct (`www.example.com/path. ok`); `BARE_HOSTNAME_RE` and `EMAIL_RE` are unaffected because their regexes stop at `\b` before any punct enters the match (regression pins added for these cases). A defensive `verifyRe.exec(trimmed)` guard alongside the fix rejects degenerate cases where trimming chewed off chars the regex required — e.g. `https://...` would otherwise pass the boundary test post-strip and anchor a broken `href: 'https://'`; the verify ensures the trimmed string still satisfies the original regex from index 0 across its full length. End-of-text under `treatEndAsBoundary` (URL at end of paragraph, user hits Enter) also now resolves correctly past trailing punct. Pinned KNOWN-ISSUE test from [RAISE-50](https://risepeople.atlassian.net/browse/RAISE-50) flipped from `expect([])` to the trimmed hit; 16 new assertions cover the punct-set, stacked-punct, no-boundary, end-of-text, cross-regex, and degenerate-scheme cases (suite: 75 → 91 tests passing).

- **Silent-reload race closed: user keystroke within ~200ms of an external write is no longer silently overwritten** ([RAISE-59](https://risepeople.atlassian.net/browse/RAISE-59)). The RAISE-56 silent-reload check reads `isTabDirty(tab)` from React state, which depends on Milkdown's 200ms-debounced `markdownUpdated` emit reaching `fileState`. A keystroke that just fired DOM events and dispatched a ProseMirror transaction could be in flight when an external write landed — the dirty check returned a stale false-negative, the silent reload proceeded, and the keystroke was lost when the editor remounted via `loadEpoch`. The fix in `App.tsx`'s `onFileChanged` handler defers the silent branch by 250ms, then re-checks `isTabDirty` against the latest tab state via a new `fileRef` (the closure-bound `file` from the effect doesn't see updates that land during the wait). ## [0.1.2] — 2026-04-27

Follow-up to v0.1.1 — finishes the macOS install UX by enabling notarization. No feature changes.

### Changed

- **macOS builds are now notarized** by Apple's notary service in addition to being code-signed. ([RAISE-24](https://risepeople.atlassian.net/browse/RAISE-24))
  - First launch on a clean Mac now shows _"macOS verified that this app is free of malware"_ with an **Open** button, instead of v0.1.1's misleading _"could not verify ... may harm your Mac"_ dialog with only Move-to-Trash. (Signing alone wasn't enough on macOS Catalina+ — Gatekeeper specifically checks for a stapled notarization ticket.)
  - The DMG container is now signed too. v0.1.1 shipped with an unsigned DMG containing a signed `.app`; both layers are signed in v0.1.2.
  - Build hosts now need `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID` env vars to produce a notarized build. Without them, builds still succeed but skip notarization (useful for local smoke tests).

### Notes

- Existing v0.1.1 installs will see the auto-update banner within ~5 seconds of next launch and can install v0.1.2 from there. The publisher identity is unchanged so Squirrel auto-update accepts the upgrade.

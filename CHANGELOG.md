# Changelog

All notable changes to Rise MD Editor are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **OS file associations for markdown** ([RAISE-44](https://risepeople.atlassian.net/browse/RAISE-44)). Installing Rise MD Editor now claims the markdown extension family at the OS level so right-click → Open With (macOS Finder), Default Apps (Windows), and double-click-to-launch flows all work. Claimed extensions: `.md`, `.markdown`, `.mdown`, `.mkd`, `.mkdn`, `.mdwn`, `.mdtxt`, `.mdtext`. **Deliberately not claimed**: `.txt` (too generic — would steal from system defaults like TextEdit / Notepad; we still _accept_ `.txt` via argv if a user manually sets us as the default for it) and `.mdx` (separate ecosystem). On macOS, electron-builder writes the `CFBundleDocumentTypes` and UTI declarations into the `.app` bundle's Info.plist; on Windows the NSIS installer writes per-user (`HKCU`) registry entries — no admin elevation needed, matches VS Code's default. Multi-select from Explorer (which concatenates every selected path into argv on a single launch) now opens all of them as tabs in one window — the previous `findFileArg` returned only the first match. The existing single-instance lock (RAISE-58 prep work) routes second-launch file paths through `app.on('second-instance')` so double-clicking a `.md` while the app is running opens a tab in the existing window rather than spawning a duplicate process. Files opened via the OS open in Read mode per RAISE-60. **Follow-up work tracked separately**: encoding fallback for UTF-16 / Latin-1 files, large-file (>10 MB) confirmation, realpath-based de-dup for symlinks, custom file icons in Finder / Explorer, Linux `.desktop` MIME-type registration, and a "make us your default?" first-launch prompt — all listed as out of scope in the ticket.
- **Drag-and-drop file/folder moves in the sidebar tree** ([RAISE-13](https://risepeople.atlassian.net/browse/RAISE-13)). Drag a file or folder onto a different folder row to move it. Dropping onto a file targets that file's parent. Drop-target folders get a tinted highlight ring while hovered. Invalid moves are disabled at drag time (no-drop cursor, no highlight) — same-parent no-ops, folder-onto-itself, folder-into-a-descendant. Name collisions surface a dialog and the existing item is preserved. Cross-device moves (workspace on one drive, destination on another) surface a clear "use your file manager instead" error rather than crashing — the copy+delete fallback is out of scope. Open tabs follow the move automatically: a file's tab path updates to the new location, and tabs for descendants of a moved folder follow too. The root row isn't draggable but IS a valid drop target (drop a file onto the workspace folder name to promote it to the top level). **Opt-drag (macOS) / Ctrl-drag (Windows / Linux)** flips the operation to a copy — the OS cursor switches from the move arrow to the `+` copy cursor live as you press / release the modifier. Same-parent copies auto-rename to `<stem> 2.<ext>`, `<stem> 3.<ext>`, etc. (lowest available integer, Finder-style); cross-folder copies require an unused name and surface a clear error on collision. Folder copies recurse through the subtree via `fs.cp`, so dragging a folder duplicates its full contents. Multi-extension files like `notes.tar.gz` keep the compound suffix intact during auto-rename — copy becomes `notes 2.tar.gz`, not the orphaned `notes.tar 2.gz`. **Drag a sidebar file INTO the editor** (instead of onto another tree row) and the editor inserts a reference to it at the drop point: in Edit mode an image file becomes a markdown image (`![name](relative/path.png)`), in Code or Split the file's relative path is inserted as plain text. Image-only for now — non-image sidebar files dropped into the editor are no-ops; future feature could extend to markdown-link or attachment-reference insertion. **Double-click on a non-markdown file in the sidebar** (e.g. `.html`, `.pdf`, `.png`) now opens it in the OS default application — your browser or VS Code for `.html`, Preview or Acrobat for `.pdf`, etc., per your system's file associations. Folders still expand/collapse on double-click; markdown files still open in-editor on single-click. The styling of non-markdown rows is updated to use the regular hover background and pointer cursor (they're actionable now via double-click) while keeping the muted text colour as a file-type hint.
- **Paste and Match Style** ([RAISE-51](https://risepeople.atlassian.net/browse/RAISE-51)). New `Cmd/Ctrl+Shift+V` accelerator pastes the clipboard content with all formatting markers dropped — no link marks, no bold / italic / strikethrough, no tables / lists / headings — bypassing the markdown / Turndown / image pipeline that regular `Cmd/Ctrl+V` runs through. Use case: copying a paragraph from a styled web article without dragging links and `<em>` markup along; pasting a code snippet that the source marked up as a table; quoting a passage without inheriting the source's link salad. Edit menu gains `Paste and Match Style` (macOS naming) / `Paste without Formatting` (Windows/Linux); the same item appears in the editor right-click context menu next to regular Paste in WYSIWYG, Source, Split, and the frontmatter textarea — gated on the clipboard actually containing text so the menu item is hidden for image-only clipboards. Image clipboards short-circuit to a no-op for paste-plain, matching Word's behaviour. In WYSIWYG the surface reads the clipboard's `text/html` slot and reduces it to its visible text content (with paragraph and heading boundaries preserved as line breaks, table cells joined with tabs), so a heading copied from inside the app pastes as `Header`, not `## Header`. In Source / Split, the `text/plain` slot inserts at the cursor verbatim — the user is editing raw markdown there and wants the markdown source. Both paths normalize `U+00A0` (non-breaking space — common web-page artifact) to ASCII space and strip `U+FEFF` (BOM). The regular Cmd/Ctrl+V pipeline (RAISE-39) is unchanged.
- **Read mode — fourth editor mode for read-only rendered markdown** ([RAISE-60](https://risepeople.atlassian.net/browse/RAISE-60), supersedes [RAISE-52](https://risepeople.atlassian.net/browse/RAISE-52)). Adds a `Read` option to the mode pill, sitting leftmost (Read → Edit → Code → Split). Renders the markdown through the same `markdown-it` pipeline as the Split-view preview pane but without an accompanying editor surface — no Monaco, no Milkdown, no contenteditable. Layout matches the WYSIWYG centered max-width column. Per-tab scroll persistence via a new `readScrollPosition` Tab field. **Mode accelerators renumbered** to match the pill order: `Cmd+1` = Read, `Cmd+2` = WYSIWYG, `Cmd+3` = Source, `Cmd+4` = Split — pre-RAISE-60 these were `Cmd+1/2/3` for WYSIWYG/Source/Split. `Cycle Mode` (`Cmd+\\`) walks all four in pill order. `Cmd+A` in Read mode selects the preview content (scoped — does not select the sidebar / mode pill / status bar the way the default `webContents.selectAll()` would). **Default mode by launch context**: files opened via the OS (macOS `app.on('open-file')` from Finder double-click / "Open With", Win/Linux argv file-association) open in Read mode; files opened in-app (sidebar click, drag-drop, `File → Open…` dialog, recents, `File → New`) keep the existing WYSIWYG default. If a file is already open and the OS triggers another open, the existing tab activates with its current mode preserved — re-opening a file you're actively editing doesn't yank you back to Read. Mechanism: an optional `fromOs` flag threaded through the `open-path` menu-action payload, consumed by `loadFile`'s new `initialMode` arg.
- **Export to HTML** ([RAISE-53](https://risepeople.atlassian.net/browse/RAISE-53)). New `File → Export → HTML…` menu item produces a portable HTML rendering of the document, visually identical to the existing PDF export (same markdown-it pipeline, same prose styling, same fonts). The modal offers two image-bundling modes: **Inline** embeds images as base64 data URIs in a single self-contained `.html` file (good for email / Slack / archive); **External** copies images into an `assets/` folder alongside the HTML and packages the result as a `.zip` (good for hosting or unpacking to edit). Same range / strip-comments / open-after toggles as the PDF modal. Mode preference is persisted in localStorage so repeat exports don't re-ask. Exported HTML uses a WYSIWYG-matching layout (centered max-width column, surface-tone code blocks) rather than the print-tuned overrides used for PDF, and its inlined `<style>` block is minified at export time — comment+whitespace stripping alone drops it from ~20KB to ~6KB without changing any rendered byte.
- **Windows installers are now signed via Azure Artifact Signing** ([RAISE-58](https://risepeople.atlassian.net/browse/RAISE-58)). SmartScreen no longer shows the "Unknown publisher" warning on first install — the signed `.exe` chains up to Microsoft's trusted root and shows _Rise People Inc._ as the verified publisher. Signing happens during the CI build via electron-builder's `signtoolOptions.sign` callback ([`scripts/sign-windows.cjs`](scripts/sign-windows.cjs)) shelling out to Microsoft's Artifact Signing dlib + `signtool.exe`. The cert lives in Microsoft's FIPS 140-2 Level 3 HSM and never touches the runner; the runner authenticates to Azure via OIDC federation (no long-lived service-principal secret). Cost is ~$10/month (Artifact Signing Basic tier). The `build-win` job declares `environment: rise-md-editor-signing` so only authorized workflow runs can exchange their OIDC token for the cert-profile signing role. Full one-time provisioning recipe in [`docs/azure-signing-setup.md`](docs/azure-signing-setup.md). _(Note: Microsoft rebranded "Trusted Signing" → "Artifact Signing" in the Azure portal; older Microsoft Learn docs and the NuGet client package `Microsoft.Trusted.Signing.Client` still use the older name.)_
- **Automated release pipeline via GitHub Actions** ([RAISE-45](https://risepeople.atlassian.net/browse/RAISE-45)). Pushing a `v*` tag now triggers a parallel macOS + Windows build on GitHub-hosted runners that assembles the artifacts into a draft GitHub Release. macOS builds are code-signed and notarized (Apple Developer ID + notarytool); Windows signing landed shortly after via RAISE-58 above. A `workflow_dispatch` entry point with a `skip_signing` input lets contributors dry-run the macOS path without burning notary minutes. Operational details — secrets, troubleshooting — live in `docs/release-process.md`.
- **Test infrastructure (vitest + CI workflow)** ([RAISE-14](https://risepeople.atlassian.net/browse/RAISE-14)). Adds vitest as the unit-test runner for pure-logic surfaces in renderer and main, with the first test covering the `looksLikeFilenameExtension` / `looksLikeKnownTld` autolink gate that originally landed in RAISE-47. Tests live alongside the source under `__tests__/` directories and are discovered via the glob in `vitest.config.ts`. New `npm test` script runs the full suite once and exits — the `vitest run` (not `vitest`) form so it doesn't drop into watch mode in CI. A new `.github/workflows/ci.yml` runs `typecheck` + `lint` + `build` + `test` on every push to a non-main branch and every PR to main, mirroring the local pre-commit gate. The release pipeline (`release.yml`) is untouched. Foundation for the dedicated fixture-coverage tickets (RAISE-35, 40, 41, 50) that will sit on top of it.

### Added

- **Silent auto-reload of externally-edited files when the local copy is clean** ([RAISE-56](https://risepeople.atlassian.net/browse/RAISE-56)). When chokidar reports that an open file changed on disk and the user hasn't typed anything since opening it, the editor now picks up the change silently — no prompt. This is the canonical Cowork workflow: Claude edits a `CLAUDE.md` or `SKILL.md` in another terminal while the user has it open in Rise MD Editor, and the user just sees the new content. Dirty tabs still get the existing "this file changed on disk — reload?" prompt so unsaved edits aren't blown away. Note: this currently only fires in Project Mode (folder open); single-file mode has no watcher today — tracked as a follow-up.

  **Known limitation**: in a narrow window (~100–200ms) where a user types in the body and an external write fires nearly simultaneously, the user's keystroke can be silently overwritten before Milkdown's 200ms-debounced emit reaches `fileState`. The `isTabDirty` check reads from React state, which hasn't yet picked up the in-flight keystroke. Unlikely in practice for human-pace editing alongside async AI edits, but the path exists. Mitigation tracked as [RAISE-59](https://risepeople.atlassian.net/browse/RAISE-59).

### Fixed

- **Auto-update banner no longer flashes briefly on cold launch when an update is detected mid-init** ([RAISE-20](https://risepeople.atlassian.net/browse/RAISE-20)). `useUpdateState` previously called `update.getState()` first and registered the `onStateChange` subscription only after — so if main flipped from `idle` to `downloading` between the IPC dispatch and its response (rare but real on a cold launch where the updater is racing the renderer attach), the stale `idle` reply would overwrite the live `downloading` state and the banner would appear for one frame then vanish. Now the subscription registers first; the initial-fetch resolution is discarded if a live event has already populated state. The same subscribe-then-fetch fix is applied to `useThemeState` ([RAISE-10](https://risepeople.atlassian.net/browse/RAISE-10) hook) so a `theme:updated` push from main during the initial `theme.get()` round-trip — e.g. an OS theme change firing the same tick the renderer attaches — is no longer clobbered.
- **Auto-update install now safely interacts with dirty tabs** ([RAISE-19](https://risepeople.atlassian.net/browse/RAISE-19)). Clicking _Restart to update_ in the auto-update banner with unsaved work open now shows the dirty-tab prompt with install-aware copy (_"Save changes before restarting to install Rise MD Editor 0.2.0?"_) instead of the generic _"You have unsaved changes."_ that left users wondering what they'd done to trigger a quit. Save / Save All / Review Each runs the existing per-tab resolution flow and then fires `autoUpdater.quitAndInstall` on success. Don't Save quits and installs immediately. Cancel keeps the app open and the banner intact in its `downloaded` state, so the user can click _Restart_ again later — the previous flow could half-tear-down the autoUpdater state and leave subsequent Restart clicks as silent no-ops until the next launch. No dirty tabs → install fires immediately with no prompt. The install path is routed through the existing window-close handler (via a new `pendingInstallAfterClose` flag in main) rather than the implicit teardown chain that `quitAndInstall(false, true)` would have driven on its own — that keeps the dialog copy in one place and avoids a Win/Linux race between `window-all-closed → app.quit()` and electron-updater spawning the installer.
- **Multi-paragraph paste into a table cell now preserves visible line breaks** (latent RAISE-46 bug, caught during RAISE-51 review). The inline-flattening helper that splices multi-paragraph paste content into a single cell looked up `schema.nodes['hard_break']` (standard ProseMirror schema name) — but Milkdown's commonmark preset names the node `'hardbreak'` (lowercase, no underscore). The defensive `if (breakType)` guard always evaluated false under Milkdown's schema, so adjacent paragraphs were silently joined with no separator: pasting `"Line one\n\nLine two"` into a cell produced `"Line oneLine two"`. Now correctly inserts a `<br>` between paragraphs, matching the original RAISE-46 AC.
- **Edit (WYSIWYG) mode now auto-focuses on mount** (RAISE-60 smoke-test follow-up). Opening a file in Edit mode — or switching to Edit from another mode — landed the user in a state where they had to click into the editor before they could type. Root cause: the `mounted` callback in `WysiwygEditor.tsx` gated `view.focus()` behind a "cursor offset > 0" check, so freshly-opened files (offset === 0) never received focus, and tabs with a saved offset positioned the cursor but never focused the view. Now focus fires unconditionally on mount; cursor restoration is the conditional part.
- **Status-bar Ln/Col no longer shows stale Monaco state in Read and Edit modes** (RAISE-60 smoke-test follow-up). The line/column indicator only makes sense in modes backed by a source view (Source, Split). In Read there's no cursor; in Edit (WYSIWYG) the ProseMirror position offset doesn't map to source line/col without re-running the markdown serializer on every keystroke. The indicator now renders blank in Read and Edit, and continues to show in Source and Split. Layout stays stable across mode swaps — the cell reserves the same horizontal slot whether populated or not.
- **HTML-export zip entries had the wrong modification time on extraction** (RAISE-53 smoke-test follow-up). Files extracted from the `External (zip bundle)` export showed timestamps shifted by the local UTC offset — a zip created at 8:31 PM PT would extract with files stamped 3:30 AM the next day. Root cause is a long-standing JSZip 3.10.x bug: it encodes the DOS time field using `getUTC*` methods, but the ZIP spec's DOS time format stores local time with no timezone marker, so extraction tools faithfully read back whatever JSZip stamped and present it as local. Fixed by pre-shifting the entry Date by the local timezone offset so JSZip's `getUTC*` calls return the wall-clock values we actually want stored. All entries in a single export now share the same mtime, matching the intuition that one archive came from one export moment.
- **Single-tilde strikethrough now renders in preview, split view, and HTML/PDF export** (RAISE-53 smoke-test follow-up). The WYSIWYG editor (Milkdown's GFM input rule) accepts both `~text~` and `~~text~~` as strikethrough, but markdown-it's built-in rule rejects single tildes (`if (len < 2) return false`). The two surfaces disagreed: the same source rendered as `<del>` in WYSIWYG and as plain text everywhere else. Fixed by adding a code-region-aware preprocessor (`expandSingleTildeStrikethrough`) that rewrites single-tilde pairs to double tildes before parsing — same boundary conditions as Milkdown's input rule (opening tilde not preceded by a word char or tilde, not followed by another tilde or whitespace; closing tilde not preceded by whitespace or tilde, not followed by a word char or tilde). Code-region split mirrors `stripComments` so tildes inside fenced or inline code (e.g. shell `~/foo`) pass through untouched.
- **WYSIWYG edits of 1–2 characters not marking the tab dirty** (RAISE-55 regression follow-up). Files without URL-shaped text (the common case for `CLAUDE.md`-style content) had no Milkdown plugin init-time `appendTransaction`, so the "first `setContent` call captures the baseline" heuristic from the original RAISE-55 fix was actually consuming the user's first keystroke as the baseline — silently marking the tab clean. Replaced with DOM-event-level user-interaction tracking: WysiwygEditor's wrapper div attaches an `input` listener (capture phase) that flips `hasUserInteractedRef` on the first descendant input from either the body or frontmatter textarea. MilkdownBody's `markdownUpdated` callback reads this ref to route emits to either the baseline path (no user input yet — init emit) or the user-edit path (real edit). Preserves the original RAISE-55 fix for URL-text files while making 1-char edits trigger dirty correctly. Caught during RAISE-56 smoke-testing before any release shipped.
- **Crash on macOS launch via Finder double-click** ([RAISE-54](https://risepeople.atlassian.net/browse/RAISE-54)). Right-click → Open With → Rise MD Editor (or double-clicking a `.md` file when the app isn't already running) no longer triggers an "Uncaught Exception: Cannot create BrowserWindow before app is ready" dialog. Root cause: the macOS `open-file` event handler funneled through `dispatchMenuAction`, which called `createWindow()` synchronously — and on macOS, `open-file` can fire before `app.whenReady()` completes. The dispatch now gates window creation on `app.isReady()` and relies on the existing `whenReady` + renderer-ready queue-drain path to surface the pending action once the window is up.
- **Spurious "Save changes?" prompt when closing files with URL-shaped text** ([RAISE-55](https://risepeople.atlassian.net/browse/RAISE-55)). Files containing bare URLs (`example.com`, `internet.com`, etc.) or that benefited from any other Milkdown plugin's init-time `appendTransaction` were marked dirty on open before the user had typed anything — closing without saving raised a misleading prompt. Root cause: Milkdown plugins like `autolinkOnTypePlugin` run on the first `docChanged` transaction after parse, adding link marks to bare URLs and dispatching a `markdownUpdated` event whose serialized markdown differs from the on-disk source. `fileState` now tracks a per-tab `editorBaseline` that captures the editor's first post-load emit as the dirty-comparison baseline, so cosmetic round-trip drift doesn't flip `isDirty`. User edits still mark the tab dirty correctly because they diverge from `editorBaseline`. The baseline is reset on file reload / external-edit refresh, and aligned with `savedContent` on every save.

### Changed

- **Renamed app to Rise MD Editor** ([RAISE-43](https://risepeople.atlassian.net/browse/RAISE-43)). The display name in the dock / start menu / About dialog / window title now reads "Rise MD Editor" (was "rAIse"). The `appId`, `productName`, npm-package `name`, and GitHub repo are all renamed to match. The `RAISE-` Jira ticket prefix and the `--rise-*` Rise design-system CSS variables stay unchanged. No user-data migration is shipped — the app is pre-release and there are no installed users with state to preserve.

## [0.1.2] — 2026-04-27

Follow-up to v0.1.1 — finishes the macOS install UX by enabling notarization. No feature changes.

### Changed

- **macOS builds are now notarized** by Apple's notary service in addition to being code-signed. ([RAISE-24](https://risepeople.atlassian.net/browse/RAISE-24))
  - First launch on a clean Mac now shows _"macOS verified that this app is free of malware"_ with an **Open** button, instead of v0.1.1's misleading _"could not verify ... may harm your Mac"_ dialog with only Move-to-Trash. (Signing alone wasn't enough on macOS Catalina+ — Gatekeeper specifically checks for a stapled notarization ticket.)
  - The DMG container is now signed too. v0.1.1 shipped with an unsigned DMG containing a signed `.app`; both layers are signed in v0.1.2.
  - Build hosts now need `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID` env vars to produce a notarized build. Without them, builds still succeed but skip notarization (useful for local smoke tests).

### Notes

- Existing v0.1.1 installs will see the auto-update banner within ~5 seconds of next launch and can install v0.1.2 from there. The publisher identity is unchanged so Squirrel auto-update accepts the upgrade.

## [0.1.1] — 2026-04-27

Tiny follow-up to v0.1.0 — code signing for macOS only, no feature changes.

### Changed

- **macOS builds are now code-signed** with the Rise People Inc Developer ID Application certificate. ([RAISE-23](https://risepeople.atlassian.net/browse/RAISE-23))
  - On first launch users still see Gatekeeper's "verified developer" dialog (one-time _"Open Anyway"_ via System Settings → Privacy & Security) because the build isn't notarized yet — but the dialog now says _"Apple verified Rise People Inc"_ instead of _"could not verify rAIse"_. Notarization is tracked as a follow-up.
  - `electron-builder.yml`'s `mac.identity` is now hardcoded; build hosts without the cert in their Keychain need `CSC_IDENTITY_AUTO_DISCOVERY=false` in the environment to skip signing for unsigned smoke builds.

### Notes

- Existing v0.1.0 installs will see the auto-update banner within ~5 seconds of next launch and can install v0.1.1 from there.
- Windows + Linux artifacts unchanged — still need to be built on their respective hosts and uploaded to the same release.

- **Tab bar with multi-file editing** — drag-to-reorder, middle-click close, dirty-dot indicator, Cmd+Alt+Arrow tab cycling on macOS / Ctrl+Tab on other platforms. Multi-tab close flow with Save All / Review Each / Don't Save / Cancel. ([RAISE-5](https://risepeople.atlassian.net/browse/RAISE-5))

- **Mode switching** — Source / WYSIWYG / Split with Cmd+1/2/3 + Cmd+\\ cycle, cursor + scroll position preserved per mode per tab, scroll-sync between source and preview in Split. ([RAISE-7](https://risepeople.atlassian.net/browse/RAISE-7))
- **File tree sidebar (Project Mode)** — chokidar 3.6.0 watching, expand/collapse, Cmd+B toggle, draggable resize, persistence of width + visibility + last-opened folder, native context menu (New / Rename / Delete / Reveal), inline name editing, OS-Trash-based delete, drag-folder-onto-window opens.
